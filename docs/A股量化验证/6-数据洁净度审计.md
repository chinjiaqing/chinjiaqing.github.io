# 6. 数据洁净度审计：注释与实现打架的一次复盘

> 背景：Step 4 前向追踪的收益口径文档一度写成"T+1 开盘买入"，而 A 股是 T+1 制度——
> 当日买当日卖不可能。这句话引发了"系统口径到底是不是 T+0？"的认知混乱。
> 本页记录：**如何定位、如何修复、以及如何用反推审计证明历史数据是干净的**。
> 发生日期：2026-09-02（纯文案修复，统计公式与判定规则零改动）

## 一、问题定位：注释 vs 公式，谁在撒谎

`step4_forward_log.py` 的 docstring 写着：

```python
# 原注释（错误/误导）
# - 判定：T+1 开盘买入，开盘 ≥ 基准×1.095 → SUSPECTED_UNFILLED（不成交，不计入 n）
# - 收益：T+1 收盘卖出 ...
```

但同文件结算函数实际是（**这段一直是对的**）：

```python
# step4_forward_log.py settle() 核心
close_t  = bars[d][1]          # T 日（信号日）收盘价 —— 成本基准
open_t1, close_t1 = bars[nxt]  # T+1 开盘/收盘
if open_t1 >= close_t * FROZEN["unfilled_open"]:   # 1.095
    r["status"] = "UNFILLED"   # 打板买不到，不计入样本
else:
    ev = close_t1 / close_t - 1 - FRICTION          # ← 成本是 close_T，不是 open_T1
```

**结论**：注释说"次日开盘买入"，公式却用"T 日收盘价"做成本——**注释错了，实现是对的**。
真实语义是 T 日盘中打板（≈涨停价 close_T）→ 隔夜 → T+1 收盘卖出的合法 T+1 持仓；
`unfilled` 闸是"T 日打板是否排得进"的代理（T+1 还一字开盘 = T 日封板太强、散户排不进）。

## 二、修复（3 处，纯文案对齐，零公式改动）

1. `step4_forward_log.py` docstring 改为：

```
- 判定：T 日盘中首板确认时以涨停价 (Close_T) 排单买入 → 隔夜持有 → T+1 收盘 (Close_T+1) 离场
- 收益：Ret = Close_{T+1}/Close_T − 1 − 0.35%（真实 T+1 跨日持仓，无同日 T+0 假设）
- unfilled_guard：T+1 开盘 ≥ 基准×1.095 → 反证 T 日散户通道打板无法成交 → 不计入 n
```

   并在日报模板头部固定输出一行**【执行口径】**，让每天的报告自带口径声明。

2. `bench_step1_leader_premium.py` 注释同步澄清（同源基准，防止换个文件又读歪）。

3. `v0.4.2_amendment.md` 增加 **V0.4.4 口径澄清**小节——协议文档层正本清源
   （改协议数值 = 新版本号 + 全量重算；但纯文字澄清零规则变更，不触发重算）。

## 三、历史账本审计：反推"隐含成本价"抓脏数据

注释是文字，账本才是事实。问题：`step4-log.csv` **没有存 close_T**，
怎么证明历史上那 7 笔 DONE 真是按"close_T 成本、T+1 收盘卖"算的？

**方法：隐含成本反推判别**——从账本字段反推它记账时用的成本价：

```python
# scripts/audit_step4_ledger.py（只读审计，复用生产 fetch/日历/冻结参数）
implied_cost = led_close / (1 + led_ev + FRICTION)
# led_close = 账本存的 T+1 收盘价；led_ev = 账本存的净收益；FRICTION = 0.0035
```

判别逻辑：
- 账本按 **close_T 成本**（正确口径）→ 反推价 ≈ 行情里的 T 日收盘价，**且 ≠ T+1 开盘价**
- 账本误按 **T+1 开盘价成本**（错误注释的说法）→ 反推价直接等于 open_T1，当场现形

逐笔结果（独立重拉行情核对，T+1 取日历真实下一交易日）：

|---|---|---|---|---|
| 08-18 | 学大教育 | DONE | 35.540 = 35.540（open_T1 37.31） | ✅ |
| 08-19 | 日丰股份 | DONE | 11.730 = 11.730 | ✅ |
| 08-20 | 汉森制药 | UNFILLED | 9.26→10.19 一字闸成立 | ✅ |

→ 历史数据与修复后口径**完全一致**，账本干净，无需任何回填。

> 而非状态机里的实际窗口（09-15 起两者分离）；"连板分布"行按固定 6 类截断显示，导致合计不等于当日涨停总数。
> **显示层问题不等于数据问题**——这是本页反复出现的主题：先分清"账本算错了"还是"报告写歪了"，再决定改不改。

> 而不是"看起来没坏"**——若没有对账习惯，这次截断会安静地留在文件里。
> 横向排查还发现另一处同型非原子写（另一个账本，当前体检干净）→ 属潜伏风险，**脚本未改，留用户裁定**。

>
> 这一轮审计的最大收获是**给"不可成交"正了名**：可成交率 **45.9%（17/37）**，与回测层 243 个交易日的
> **43.6%** 落在同一量级。两个独立样本给出同一个数，说明 UNFILLED **不是脏数据、不是缺口、也不是待修复的 bug**，
> 而是**信号定义自带的结构属性**（最早封板的那一档，恰恰是最挤不进去的一档）。
> 审计上必须严格区分两类"没有数据"：
>
> | 类型 | 特征 | 处置 |
> |---|---|---|
> | **结构性不可成交** | 有信号、有行情、闸门明确判为排不进 | **合法状态**，计入分母、不计入样本 |
> | **缺失/落空** | 应有而没有（字段缺、基准价取不到、任务未运行） | **异常**，需标注、留证、不补录 |
>
> 混同这两类的后果很具体：若把 UNFILLED 当"数据缺失"去补，会凭空造出一批"本可以买到"的样本，
> 直接虚高可成交率与净 Ev；若把真正的缺失当"结构性不可成交"，则会悄悄丢掉异常信号。
> **判据：先看有没有信号与行情（有 → 结构性），再看该有的值在不在（不在 → 缺失）。**
>
> 本轮还出现了一次**真正的"应有而没有"**（见《7. 模拟盘执行线》§三·任务缺口）：
> 某个交易日的早盘决策任务没有任何产出，账本里那一行**根本不存在**。
> 审计口径：**缺失行不补录、不推断、不代跑**，只在连 B 计数上显式标注"账本口径 N / 实际可能 N+1"。
> 理由与全篇一致——**账本的可信度来自"每一行都能被独立复算"，而不是"看起来连续"**。
> 补一行会让序列好看，但会让整条序列失去可复算性。
>

> 成本价/收益公式仍零变动，无需回填。

> 本轮审计最重要的一条不是"又自洽了"，而是**发现"n 也会漂"**：
> 多篇文档长期写着"累计超额用 **13** 个有效样本"，逐行核对实际是 **17** 笔有效
> （唯一落空的仍是 09-14 那笔"落空即永不再算"）。**数值 0.020087 从头到尾都是对的，错的只是描述它的那个 n。**
> → 沉淀为一条审计纪律：**核数值的同时必须核 n**。
> "数字带 n"常被当成形式要求，但这里给出了它真正的理由——**n 会随样本增长而悄悄失效，而数值可能一点都不变**；
> 只核数值的审计，会让一句"13 个有效样本"在四个月里无人质疑地传下去。
>
> 另一条顺带收获：可成交率 **42.9%（18/42）** 与回测层 243 个交易日的 **43.6%** 相差 **0.7pp**。
> 上一轮（10-16）这个对比还是 45.9% vs 43.6%，当时说"同一量级"；这一轮两个独立口径**直接压到了一起**。
> 这不是巧合，而是"可成交率是一个结构常数"这一判断的又一次独立验证——
> **UNFILLED 既不是脏数据、也不是缺口，它就是这条线的物理常数。**

## 四、沉淀

1. **注释与实现打架是最高危的隐性 bug 形态**——它不改结果，但会污染每一个读代码的人
   对"系统到底在算什么"的理解，进而引发对结论的信任危机。
2. **"反推隐含参数 + 独立重拉对账"是审计历史账本的通用手法**：账本没存关键输入时，
   用输出反推输入，再与独立数据源交叉验证——两种错误口径会被判别式区分开。
3. 审计脚本保留为 `scripts/audit_step4_ledger.py`，每笔新结算后都能复跑复查。
