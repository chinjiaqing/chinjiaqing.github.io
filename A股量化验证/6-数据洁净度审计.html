6. 数据洁净度审计：注释与实现打架的一次复盘 ​

背景：Step 4 前向追踪的收益口径文档一度写成"T+1 开盘买入"，而 A 股是 T+1 制度—— 当日买当日卖不可能。这句话引发了"系统口径到底是不是 T+0？"的认知混乱。 本页记录：如何定位、如何修复、以及如何用反推审计证明历史数据是干净的。 发生日期：2026-09-02（纯文案修复，统计公式与判定规则零改动）

一、问题定位：注释 vs 公式，谁在撒谎 ​

step4_forward_log.py 的 docstring 写着：

python
# 原注释（错误/误导）
# - 判定：T+1 开盘买入，开盘 ≥ 基准×1.095 → SUSPECTED_UNFILLED（不成交，不计入 n）
# - 收益：T+1 收盘卖出 ...

但同文件结算函数实际是（这段一直是对的）：

python
# step4_forward_log.py settle() 核心
close_t  = bars[d][1]          # T 日（信号日）收盘价 —— 成本基准
open_t1, close_t1 = bars[nxt]  # T+1 开盘/收盘
if open_t1 >= close_t * FROZEN["unfilled_open"]:   # 1.095
    r["status"] = "UNFILLED"   # 打板买不到，不计入样本
else:
    ev = close_t1 / close_t - 1 - FRICTION          # ← 成本是 close_T，不是 open_T1

结论：注释说"次日开盘买入"，公式却用"T 日收盘价"做成本——注释错了，实现是对的。 真实语义是 T 日盘中打板（≈涨停价 close_T）→ 隔夜 → T+1 收盘卖出的合法 T+1 持仓； unfilled 闸是"T 日打板是否排得进"的代理（T+1 还一字开盘 = T 日封板太强、散户排不进）。

二、修复（3 处，纯文案对齐，零公式改动） ​

  1. step4_forward_log.py docstring 改为：
- 判定：T 日盘中首板确认时以涨停价 (Close_T) 排单买入 → 隔夜持有 → T+1 收盘 (Close_T+1) 离场
- 收益：Ret = Close_{T+1}/Close_T − 1 − 0.35%（真实 T+1 跨日持仓，无同日 T+0 假设）
- unfilled_guard：T+1 开盘 ≥ 基准×1.095 → 反证 T 日散户通道打板无法成交 → 不计入 n

并在日报模板头部固定输出一行**【执行口径】**，让每天的报告自带口径声明。

  1. bench_step1_leader_premium.py 注释同步澄清（同源基准，防止换个文件又读歪）。

  2. v0.4.2_amendment.md 增加 V0.4.4 口径澄清小节——协议文档层正本清源 （改协议数值 = 新版本号 + 全量重算；但纯文字澄清零规则变更，不触发重算）。

三、历史账本审计：反推"隐含成本价"抓脏数据 ​

注释是文字，账本才是事实。问题：step4-log.csv 没有存 close_T， 怎么证明历史上那 7 笔 DONE 真是按"close_T 成本、T+1 收盘卖"算的？

方法：隐含成本反推判别——从账本字段反推它记账时用的成本价：

python
# scripts/audit_step4_ledger.py（只读审计，复用生产 fetch/日历/冻结参数）
implied_cost = led_close / (1 + led_ev + FRICTION)
# led_close = 账本存的 T+1 收盘价；led_ev = 账本存的净收益；FRICTION = 0.0035

判别逻辑：

  • 账本按 close_T 成本（正确口径）→ 反推价 ≈ 行情里的 T 日收盘价，且 ≠ T+1 开盘价
  • 账本误按 T+1 开盘价成本（错误注释的说法）→ 反推价直接等于 open_T1，当场现形

逐笔结果（独立重拉行情核对，T+1 取日历真实下一交易日）：

审计结论：11 笔 PASS / 0 笔 FAIL / 1 笔待结算。 每笔 ev_close 重算到 6~7 位小数全等、excess 全等、4 笔 UNFILLED 一字闸全部复核成立。 → 历史数据与修复后口径完全一致，账本干净，无需任何回填。

续（2026-09-03）：表内"待结算"的欢瑞世纪（09-02 信号）已随 09-03 收盘结算为第 8 个可成交样本 （净收益 −2.66%）。11/11 PASS 基线不受影响，新样本将在终审前由审计脚本统一复跑纳入。

续（2026-09-11）：此后账本继续 append-only，新增样本 #9 集泰股份（−10.34%）、#10 恒盛能源（+8.28%）， 以及连续 5 笔 UNFILLED（一字闸复核成立）。收益口径零变动，无需回填；V0.4.6/V0.4.7 两次判据修订 只动"停机机制"、不触及成本价/收益公式，故不触发历史重算——这正是"改协议 = 新版本号 + 全量重算" 纪律的边界：改判定规则要重算，改停机机制（不进入收益计算）只留卷宗。 当前账本状态：10 笔可成交 / 8 笔 UNFILLED / 1 笔在途，审计脚本可随时复跑。

续（2026-09-18）：样本继续推进至 13 笔可成交（新增 #11 山子高科 +5.61%、#12 中新赛克 −10.33%、 #13 华瓷股份 +9.67%），另有 11 笔 UNFILLED（合计 24 个信号日 = 当前窗口 24，算术自洽）。 成本价/收益公式仍零变动，无需回填。但本次审计暴露了一处新形态的"落空即永不再算"缺口：

  • 现象：结算函数只处理仍处于 SIGNAL 状态的行。若结算当日基准指数收盘价取不到， 该行的超额字段会落空，且此后永不再补算（09-14 山子高科即此例）。
  • 后果：累计超额实际由 12 个有效样本而非 13 个算出，比正确值偏低约 0.22pp。 对 PASS 判定无影响（三条生死线仍满足），但属口径偏差。
  • 处置：修复需改结算脚本或手工回填，属判据外变更 → 留用户拍板，本次未动。

另一类新暴露的是纯显示层口径不一致（不影响统计）：报告"窗口"字段渲染的是预注册阈值常量、 而非状态机里的实际窗口（09-15 起两者分离）；"连板分布"行按固定 6 类截断显示，导致合计不等于当日涨停总数。 显示层问题不等于数据问题——这是本页反复出现的主题：先分清"账本算错了"还是"报告写歪了"，再决定改不改。

续（2026-09-24）：账本推进至 14 笔可成交（新增 #14 禾盛新材 −4.46%，本线首个负样本）、 13 笔 UNFILLED、1 笔在途（09-24 信号待结算）——合计 28 个信号日 = 当前窗口 28，算术自洽。 成本价/收益公式仍零变动，无需回填；前述"excess 落空即永不再算"缺口仍存在（累计超额用 13 个有效样本）。

这一轮还暴露了一次更接近"数据问题"的事故（见《7. 模拟盘执行线》§三·账本写入事故）： 执行线账本因备注字段含未转义的半角逗号导致解析多出字段、叠加非原子写回， 一次写入失败就把 25 行截断成 11 行（丢 14 行）。已按三段取证恢复（逐字节保留 / 备份取回 / 依当日决策记录重建并加标记）， 恢复后 25 行 × 9 列全量校验通过。这正是本页第二条审计手法的又一次实战：账本的可信度来自"能被独立复算"， 而不是"看起来没坏"——若没有对账习惯，这次截断会安静地留在文件里。 横向排查还发现另一处同型非原子写（另一个账本，当前体检干净）→ 属潜伏风险，脚本未改，留用户裁定。

续（2026-09-30）：账本推进至 16 笔可成交（新增 #15 泰慕士 −10.35%、#16 博纳影业 +3.90%）、 14 笔 UNFILLED、1 笔在途（09-30 信号待结算）——合计 31 个信号日 = 当前窗口 31，算术自洽。 成本价/收益公式仍零变动，无需回填；"excess 落空即永不再算"缺口仍存在（累计超额仍用 13 个有效样本）。 本轮新增的是一处上游数据缺字段（某涨停股的连板高度字段缺失，见《1. 首板先锋》工程节）， 处理原则与全篇一致：宁可少一个字段，也不自造一个值——补值等于伪造数据，比缺字段更危险。

续（2026-10-16）：账本推进至 17 笔可成交（新增 #17 九阳股份 +5.84%）、20 笔 UNFILLED、 1 笔在途（10-16 信号待结算）——合计 38 个信号日 = 当前窗口 38，算术自洽。 成本价/收益公式仍零变动，无需回填；"excess 落空即永不再算"缺口仍存在（累计超额仍用 13 个有效样本）。

这一轮审计的最大收获是给"不可成交"正了名：可成交率 45.9%（17/37），与回测层 243 个交易日的 43.6% 落在同一量级。两个独立样本给出同一个数，说明 UNFILLED 不是脏数据、不是缺口、也不是待修复的 bug， 而是信号定义自带的结构属性（最早封板的那一档，恰恰是最挤不进去的一档）。 审计上必须严格区分两类"没有数据"：

类型特征处置
结构性不可成交有信号、有行情、闸门明确判为排不进合法状态，计入分母、不计入样本
缺失/落空应有而没有（字段缺、基准价取不到、任务未运行）异常，需标注、留证、不补录

混同这两类的后果很具体：若把 UNFILLED 当"数据缺失"去补，会凭空造出一批"本可以买到"的样本， 直接虚高可成交率与净 Ev；若把真正的缺失当"结构性不可成交"，则会悄悄丢掉异常信号。 判据：先看有没有信号与行情（有 → 结构性），再看该有的值在不在（不在 → 缺失）。

本轮还出现了一次真正的"应有而没有"（见《7. 模拟盘执行线》§三·任务缺口）： 某个交易日的早盘决策任务没有任何产出，账本里那一行根本不存在。 审计口径：缺失行不补录、不推断、不代跑，只在连 B 计数上显式标注"账本口径 N / 实际可能 N+1"。 理由与全篇一致——账本的可信度来自"每一行都能被独立复算"，而不是"看起来连续"。 补一行会让序列好看，但会让整条序列失去可复算性。

续（2026-10-23）：账本推进至 18 笔可成交（新增 #18 新华传媒 +2.42%）、24 笔 UNFILLED、 1 笔在途（10-23 信号待结算）——合计 43 个信号日 = 当前窗口 43，算术自洽。 成本价/收益公式仍零变动，无需回填。

本轮审计最重要的一条不是"又自洽了"，而是发现"n 也会漂"： 多篇文档长期写着"累计超额用 13 个有效样本"，逐行核对实际是 17 笔有效 （唯一落空的仍是 09-14 那笔"落空即永不再算"）。数值 0.020087 从头到尾都是对的，错的只是描述它的那个 n。 → 沉淀为一条审计纪律：核数值的同时必须核 n。 "数字带 n"常被当成形式要求，但这里给出了它真正的理由——n 会随样本增长而悄悄失效，而数值可能一点都不变； 只核数值的审计，会让一句"13 个有效样本"在四个月里无人质疑地传下去。

另一条顺带收获：可成交率 42.9%（18/42） 与回测层 243 个交易日的 43.6% 相差 0.7pp。 上一轮（10-16）这个对比还是 45.9% vs 43.6%，当时说"同一量级"；这一轮两个独立口径直接压到了一起。 这不是巧合，而是"可成交率是一个结构常数"这一判断的又一次独立验证—— UNFILLED 既不是脏数据、也不是缺口，它就是这条线的物理常数。

续（2026-10-30）：账本推进至 22 笔可成交（新增 #19 湘佳股份 +1.61%、#20 上海九百 +9.65%、 #21 金安国纪 −1.19%、#22 实丰文化 −10.34%）、25 笔 UNFILLED、1 笔在途（10-30 信号待结算）—— 合计 48 个信号日 = 当前窗口 48，算术自洽。成本价/收益公式仍零变动，无需回填。

但本轮审计最有价值的发现，恰恰是"自洽"这次什么都没证明。

上面这一整段通过项——列数对得上、成本价反推一致、算术自洽、无脏数据——检查的全是"账记得对不对"， 没有一条在检查"这笔该不该记"。而 10-30 那笔 −10.34% 的问题属于后者： 账记得完全正确（成本 16.92、卖出 15.23、收益 −10.34%，逐位可复算）， 但它记的是一笔"实际上根本买不到"的交易——信号日是一字板、封单比 18.65%，散户通道排不进； 而判据只认"次日是否还在继续一字"，次日低开就判成了可成交（详见《1. 首板先锋》§协议盲区）。

这是审计维度上的一次升级：

层级检查什么能否自动校验本例结论
记账正确性列数 / 成本价 / 算术自洽✅ 可脚本化、可复跑通过
判据正确性这笔样本该不该存在❌ 只能靠"数字反常"倒查不通过

换句话说："自洽"是最低标准，不是充分标准。 一份 100% 自洽的账本，可以系统性地偏—— 而偏差不会报错、不会缺行、不会让任何校验变红。它只会安静地出现在分子或分母里。

这次是靠什么发现的？靠"数字反常"。 单笔 −10.34% 落在一条正在退潮的曲线上，太扎眼， 才去反查信号日的封板状态，才看到"一字板 + 封单比 18.65%"。如果这笔只亏 2%，它永远不会被查。 这正是判据类缺陷最危险的地方：它不制造异常，只制造偏差—— 而只有足够大的偏差，才会伪装成异常，被人注意到。

顺带一处需要打折的旧结论：可成交率从 42.9% 回到 46.8%（22/47），与回测层 43.6% 差 3.2pp。 上一轮说"两个独立口径直接压到了一起、可成交率是结构常数"，现在看说过头了—— 它稳定在 43%~47% 这个带里，不是稳定在某一个点上；而且这个数里还含着上文那批"不该计入"的样本， 修正后只会更低。一个量级判断，不该被一次 0.7pp 的巧合升级成"常数"。

续（2026-11-06）：账本推进至 25 笔可成交（新增 #23 盛洋科技 −2.11%、#24 广聚能源 +2.72%、 #25 金螳螂 −6.48%）、27 笔 UNFILLED、1 笔在途（11-06 信号待结算）—— 合计 53 个信号日 = 当前窗口 53，算术自洽。成本价/收益公式仍零变动，无需回填。

这一轮把上一轮那个"判据正确性"的问题从个案推成了占比。 上一轮说"自洽不等于正确"， 当时只有一个反面样本（实丰文化）；现在走同一路径（信号日一字板 → 次日低开 → 判 FILLED）的已有 5 笔， 占可成交样本 20%，而且第 4、5 笔首次落在"可买区间内"。

维度上一轮（10-30）本轮（11-06）
盲区样本数25
占可成交样本9.1%20.0%
是否有落在可买区间内的否是（2 例）
5 笔均值—−2.92%（其余 20 笔 +1.94%）

一个反直觉的审计结论：这批"不该记"的样本，均值比其余样本低 4.86pp。 也就是说，口径缺陷一直在让账本变差，而不是变好。剔除后净 Ev 从 +0.97% 升到 +1.94%（纯算术推演）。

这条对审计方法本身的意义大于对这条线的意义：缺陷的方向决定了它被发现的概率。 让结论变差的缺陷会被当成"运气不好"，在账本里安静地躺两个月； 让结论变好的缺陷才会被当成"异常"，被人追着查。所以"数字变差了"永远不是可靠的审计入口—— 本例恰恰相反，是靠"5 笔走同一条路径"这个结构特征发现的，而不是靠某笔亏得特别多。 上一轮说"只有足够大的偏差才会伪装成异常、被人注意到"——这句话需要修正： 真正的入口是样本的路径重复，不是单笔的幅度。一笔 −2.11% 的亏损永远不会引人注意， 但"第 5 次走同一条路"会。

另一条仍在的旧账："n 会漂"这次又漂了（21 → 24 个有效样本）。 数值 0.015014 是脚本现算的，一直对；错的是文档里"21 个有效样本"那句话。 每新增一笔带超额的样本，这句话就该 +1，而它不会自己变。

四、沉淀 ​

  1. 注释与实现打架是最高危的隐性 bug 形态——它不改结果，但会污染每一个读代码的人 对"系统到底在算什么"的理解，进而引发对结论的信任危机。
  2. "反推隐含参数 + 独立重拉对账"是审计历史账本的通用手法：账本没存关键输入时， 用输出反推输入，再与独立数据源交叉验证——两种错误口径会被判别式区分开。
  3. 审计脚本保留为 scripts/audit_step4_ledger.py，每笔新结算后都能复跑复查。
  4. "自洽"是最低标准，不是充分标准（2026-10-30 新增）：列数对、算术对、成本价反推对， 只能证明"账记得没错"，不能证明"这笔该记"。判据层面的偏差不会报错、不会缺行、不会让校验变红， 它只会安静地污染分子或分母。发现它靠的不是校验脚本，而是**"数字反常"的倒查**—— 而这意味着：偏差越小，越没人查。
  5. 审计要分层：记账正确性可以脚本化、可复跑；判据正确性只能靠人来问"这个数字合不合理"。 两层混为一谈的后果，就是一份 100% 通过审计、却系统性偏离的账本。
  6. 缺陷的方向决定它被发现的概率（2026-11-06 新增）：让结论变差的缺陷会被当成"运气不好"， 在账本里安静躺着；让结论变好的缺陷才会被当成"异常"追查。 所以**"数字变差了"不是可靠的审计入口**——真正的入口是样本的路径重复 （"第 5 笔走同一条路"），而不是单笔的幅度（一笔 −2.11% 永远不会引人注意）。
  7. 同一处判据缺陷会同时污染两条线（2026-11-06 新增）：一字板"买不到却记为可成交"这件事， 在研究线表现为"样本不该在分母里"，在执行线表现为"这只票被排进了可执行候选"。 两条线各自都没错，错的是同一个上游判据——所以修的时候不能只修下游表现。
